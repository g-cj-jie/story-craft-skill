# 小说内容审查 Skill

## 适用场景

- 长篇小说章节正文完成后，进行质量审查
- 评审报告生成后的整改验证
- 批量章节质量评估
- 两阶段评审（脚本+LLM）处理误报

## 前置条件

- 章纲文件存在于 `故事大纲/章纲/ch-{n}.md`
- 正文文件存在于 `章节正文/第{n}章.md`
- 字数目标：每章 3000-6000 字
- 硬阻断阈值：<3000 字或 >6000 字（不进入LLM复核，直接判定不通过）

## 7维度评审体系

| 维度 | 满分 | 权重说明 |
|------|------|----------|
| 章纲一致性 | 30分 | 关键场景完整性（-5/个）、伏笔操作体现（-3）、场景顺序（-5） |
| 三层叙事完整性 | 20分 | 硬数据层10分+因果逻辑层5分+人物价值层5分，隐晦钩子不扣分 |
| 世界观一致性 | 15分 | 异世界/系统/位面不得出现现代物品或其他世界内容 |
| 人物一致性 | 10分 | 身份/能力/性格/语言风格不得崩坏 |
| 文风一致性 | 10分 | 无序号标记、破折号≤5个/千字、无重复句式 |
| 字数达标 | 5分 | 3000-6000字满分，<3000或>6000硬阻断 |
| 伏笔/子剧情 | 10分 | 伏笔自然度+子剧情推进合理性 |

## 硬阻断（自动不合格，不进入LLM复核）

- 正文字数 < 3000 字（需扩充）
- 正文字数 > 6000 字（需拆分或精简）
- 正文完全偏移章纲（关键场景全部缺失）
- 出现严重世界观破坏（异世界出现手机、电脑等）
- 人物行为严重违背已定性格

## 步骤

### 1. 两阶段批量评审（推荐）

运行两阶段评审脚本，自动处理脚本误报：

```bash
# 基本用法（执行两阶段评审）
python3 /root/.hermes/skills/novel-writing/novel-review/references/two_stage_review.py \
  --start 1 --end 100

# 自动更新规则（将LLM判断依据扩充到脚本）
python3 /root/.hermes/skills/novel-writing/novel-review/references/two_stage_review.py \
  --start 1 --end 100 --update-rules

# 只运行脚本检测（不调用LLM）
python3 /root/.hermes/skills/novel-writing/novel-review/references/two_stage_review.py \
  --start 1 --end 100 --report-only

# 限制LLM评审章节数（避免过多API调用）
python3 /root/.hermes/skills/novel-writing/novel-review/references/two_stage_review.py \
  --start 1 --end 100 --max-llm-chapters 10
```

**两阶段评审流程（三步骤）：**

1. **阶段1 - 字数脚本检测**：Python脚本检查字数
   - 硬阻断章节（字数<3000或>6000）直接标记失败，不送LLM，必须重写/扩充/拆分
   - 字数达标 → 进入阶段2
2. **阶段2 - 内容脚本检测**：关键词匹配，快速筛选
   - 章纲关键场景缺失、世界观违规、主角名缺失、结尾无钩子、破折号过多等
   - 评分≥80分 → 通过
   - 评分<80分 → 进入阶段3（LLM复核）
3. **阶段3 - LLM语义复核**：AI对失败章节进行语义评审
   - LLM认为通过（误报）→ 自动更新脚本规则（扩充同义词/放宽关键词），章节通过
   - LLM认为失败（确认）→ 标记需要重写，根据LLM评审意见修改正文
   - 判定不一致 → 需要人工复核

**输出报告：**
- 脚本检测结果
- 硬阻断章节清单（字数问题，直接失败）
- LLM复核结果
- 误报详情
- 规则更新统计
- 最终结论（通过率）

### 2. 单章精读审查（复杂章节）

如果需要对单章进行深度审查，按照以下流程：

**第一步：准备阶段**
- 读取章纲 `故事大纲/章纲/ch-{n}.md`
- 读取正文 `章节正文/第{n}章.md`
- 确认字数、关键场景、伏笔操作、三层叙事标记

**第二步：逐维度检查**

#### 维度1：章纲一致性（30分）

检查项：
- [ ] 正文是否覆盖章纲中所有「关键场景」（≥80%覆盖）
- [ ] 伏笔操作是否在正文中有对应体现
- [ ] 无凭空添加的重大情节（偏离章纲>20%）
- [ ] 场景顺序与章纲基本一致
- [ ] 章末是否有情节钩子（悬念/转折/伏笔），结尾诗句不算情节钩子

扣分规则：
- 关键场景缺失：-5分/个
- 伏笔操作未体现：-3分
- 场景顺序混乱：-5分
- 无情节钩子：-5分

#### 维度2：三层叙事完整性（20分）

| 层次 | 满分 | 检查内容 |
|------|------|----------|
| 硬数据层 | 10分 | 78点属性、任务系统、职业系统、技能熟练度等数据在推进 |
| 因果逻辑层 | 5分 | 起因→经过→结果完整，无逻辑断裂 |
| 人物价值层 | 5分 | 人物在本章获得成长或价值提升（正向或负向） |

扣分规则：
- 硬数据层无推进：-10分
- 因果逻辑断裂：-5分
- 人物无成长：-5分
- 仅是过渡章（无实质内容）：-8分

#### 维度3：世界观一致性（15分）

禁止出现的现代/异世界内容：
- `手机`、`电脑`、`汽车`、`飞机`、`电视`、`冰箱`、`空调`、`互联网`
- `地球`、`中国`、`美国`、`日本`、`欧洲`
- 现代科技术语（除合理隐喻外）

扣分规则：
- 出现1个现代物品：-5分
- 出现其他世界内容：-2分
- 世界观设定前后矛盾：-10分

#### 维度4：人物一致性（10分）

检查项：
- [ ] 主角身份（死灵法师/穿越者/地球灵魂）未混淆
- [ ] 能力范围未越界（突然使用未获得的技能）
- [ ] 性格前后一致（胆小的突然变勇猛需有合理铺垫）
- [ ] 语言风格符合身份（古代人不说现代用语）

扣分规则：
- 身份混淆：-5分
- 能力越界：-5分
- 性格突变无铺垫：-3分
- 语言风格不符：-2分

#### 维度5：文风一致性（10分）

检查项：
- [ ] 无序号标记分段（如"一、""二、"）
- [ ] 叙述节奏自然，无明显拖沓或跳跃
- [ ] 描写密度适中（非全对话或全叙述）
- [ ] 破折号使用合理（≤5个/千字）
- [ ] 无重复句式（连续3段以上相同句式开头）

扣分规则：
- 出现序号标记：-2分
- 节奏异常：-3分
- 描写密度失衡：-2分
- 破折号过多：-5分
- 重复句式：-2分

#### 维度6：字数达标（5分）

- 3000-6000字：满分5分
- <3000字：0分（硬阻断，需扩充）
- >6000字：0分（硬阻断，需拆分或精简）

#### 维度7：伏笔/子剧情（10分）

检查项：
- [ ] 本章伏笔操作是否自然（不粗暴、不敷衍）
- [ ] 埋设伏笔时有足够铺垫（非突然出现）
- [ ] 子剧情推进合理（无断崖式跳跃）
- [ ] 伏笔回收/埋设节奏合理

扣分规则：
- 伏笔操作粗暴：-3分
- 铺垫不足：-2分
- 子剧情跳跃：-5分
- 节奏失衡：-2分

| 世界观一致性 | XX | 15 | xxx |
| 人物一致性 | XX | 10 | xxx |

### 4. 评审后的整改流程

**整改 → 验证闭环：**

1. **评审不通过** → 输出具体问题清单和修改建议
2. **执行修改** → 修改正文内容
3. **再次评审** → 只检查之前扣分的维度
4. **全部通过** → 进入下一章
5. **仍不通过** → 重复步骤1-4

**评审报告保存路径：**
```
评审报告/{date}_ch{N}_评审报告.md
```

## 注意事项

1. **硬阻断不可覆盖**：字数<3000或>6000直接不合格，不送LLM复核，必须重写/扩充/拆分
2. **两阶段评审优先**：使用 two_stage_review.py 而非 batch_review.py
3. **规则自动扩充**：启用 --update-rules 参数，LLM误报会自动扩充脚本规则
4. **LLM评审限制**：使用 --max-llm-chapters 控制API调用次数
5. **评审报告编号**：按日期+章节范围命名，便于追溯
6. **整改记录**：整改后的评审报告需注明"整改验证"
7. **纯过渡章判定**：段落数<15的章节自动标记为"疑似纯过渡章"，需重点检查三层叙事完整性
8. **隐晦钩子**：结尾钩子检测已扩充关键词列表，但仍可能遗漏极隐晦的钩子，需人工复核
