# 批量章节精简工作流

## 适用场景

评审报告发现硬阻断章节（字数>6000字）需要批量精简到3000-6000字范围。

## 工作流

### 1. 提取硬阻断章节列表

从评审报告中提取所有"不合格（硬阻断）"的章节号。

### 2. 并行处理（每批3章）

使用 `delegate_task` 并行处理，每批最多3个子Agent：

```python
delegate_task(tasks=[
    {
        "goal": "精简小说第{N}章正文，从{字数}字精简到3000-5000字范围。保留章纲要求的关键场景，删除冗余描写，保留核心剧情和结尾钩子。",
        "context": "章纲路径：{path}\n正文路径：{path}\n整改要求：...",
        "toolsets": ["terminal", "file"]
    },
    # ... 最多3个任务
])
```

### 3. 子Agent执行步骤

每个子Agent：
1. 读取章纲（`故事大纲/章纲/ch-{N}.md`）
2. 读取当前正文（`章节正文/第{N}章.md`）
3. 分析章纲与正文是否匹配
4. 精简正文：
   - 删除重复环境描写
   - 压缩冗余心理活动
   - 合并相似场景
   - 保留关键场景、伏笔操作、结尾钩子
5. 控制破折号密度（≤3个/千字）
6. 写入修改后的正文
7. 验证字数（`wc -m`）

### 4. 进度反馈

每处理完一批（3章），更新进度汇总表：
| 章节 | 原字数 | 现字数 | 状态 |

### 5. 质量验证

精简完成后，可用 `wc -m` 批量验证所有修改章节的字数：

```bash
for ch in 54 70 74 75 ...; do
  chars=$(wc -m < "章节正文/第${ch}章.md")
  echo "第${ch}章: ${chars}字符"
done
```

## 常见陷阱

### 章纲与正文不匹配

评审中经常发现章纲描述的内容与正文完全不同。原因可能是：
- 章纲文件被错误覆盖
- 章节编号错位
- 正文在之前某次修改中被替换

**处理原则**：保留现有正文内容进行精简，不按章纲重写。在评审报告中标注不匹配问题。

### 精简不足

初次精简可能仍超过5000字。需要二次精简，重点删除：
- 重复的感官描写（"冰冷的""刺骨的"多次出现）
- 冗长的WoW世界观解释
- 过度的选项分析（"要么A要么B"反复权衡）
- 重复的结尾离场描写

### 破折号超标

原文常有破折号密度>10个/千字的问题。精简时需要：
- 将部分破折号替换为逗号或句号
- 保留对话中断和戏剧性强调处的破折号
- 目标≤3个/千字

## 预期速度

- 每批3章约需2-4分钟
- 16章约需5批，总计15-25分钟
- 含进度反馈和验证约30分钟
