# 批量章节整改工作流

## 适用场景

评审报告发现章节问题需要批量整改。覆盖三种整改模式：
1. **精简模式** — 字数超标（>6000字），需压缩到3000-6000字
2. **补充模式** — 缺少关键场景/结尾钩子/伏笔操作，需定向补充
3. **重写模式** — 章纲与正文完全不匹配，需按章纲重写

## 工作流

### 1. 分析评审报告

从评审报告中提取问题章节，按严重程度排序：
- **硬阻断**（字数>6000或<3000）→ 精简/扩充模式
- **需修改**（缺少场景/钩子/伏笔）→ 补充模式
- **章纲不匹配** → 重写模式

### 2. 并行处理（每批3章）

使用 `delegate_task` 并行处理，每批最多3个子Agent：

```python
delegate_task(tasks=[
    {
        "goal": "修改小说第{N}章正文，补充章纲要求的关键场景、结尾钩子和伏笔操作。",
        "context": "章纲路径：{path}\n正文路径：{path}\n评审问题：{问题列表}\n整改要求：...",
        "toolsets": ["terminal", "file"]
    },
    # ... 最多3个任务
])
```

### 3. 子Agent执行步骤

每个子Agent：
1. 读取章纲（`故事大纲/章纲/ch-{N}.md`）
2. 读取当前正文（`章节正文/第{N}章.md`）
3. **人工复核**关键场景（评审脚本的关键词匹配经常误判）
4. 根据模式执行：
   - **精简**：删除冗余描写、压缩心理活动、合并相似场景
   - **补充**：定向补充缺失的场景/钩子/伏笔
   - **重写**：完全按章纲重新编写
5. 控制破折号密度（≤3个/千字）
6. 写入修改后的正文
7. 验证字数（`wc -m`）

### 4. 进度反馈

每处理完一批（3章），更新进度汇总表：
| 章节 | 主要修改 | 状态 |

### 5. 质量验证

整改完成后，重新运行评审脚本验证：
```bash
cd /path/to/novel && python3 /root/.hermes/skills/novel-writing/novel-review/references/batch_review.py --start {start} --end {end}
```

## 三种整改模式详解

### 模式1：精简（字数超标）

目标：6000+字 → 3000-6000字

精简重点：
- 重复的感官描写（"冰冷的""刺骨的"多次出现）
- 冗长的世界观解释
- 过度的选项分析（"要么A要么B"反复权衡）
- 重复的结尾离场描写
- 大段环境描写压缩为1-2句

### 模式2：补充（缺少要素）

目标：补充缺失的关键场景、结尾钩子、伏笔操作

补充策略：
- **关键场景**：先检查是否已存在（只是表述不同），如确实缺失则按章纲补充
- **结尾钩子**：将平淡结尾替换为悬念场景（三层递进：感知异常→发现线索→行动承诺）
- **伏笔操作**：在相关段落中加入伏笔关键词和暗示

### 模式3：重写（章纲不匹配）

目标：按章纲完全重写正文

重写步骤：
1. 读取章纲，提取关键场景、伏笔操作、三层叙事要求
2. 读取前后章正文，确保故事连贯
3. 按章纲编写新正文
4. 保留前章结尾钩子的呼应
5. 为下章埋设衔接伏笔

## 预期速度

- 每批3章约需1-3分钟
- 16章精简约需5批，总计15-25分钟
- 32章补充/重写约需11批，总计30-60分钟
- 含进度反馈和验证约1-2小时

## 常见陷阱

### 1. 评审脚本关键词匹配误判

`batch_review.py` 的关键场景检测基于关键词匹配，经常出现：
- 正文中用不同表述描述同一场景 → 被判为"缺失"
- 结尾钩子文学性强但不含固定关键词 → 被判为"缺失"
- 伏笔操作用暗示而非明示 → 被判为"未体现"

**2026-06-02实测数据（50章批量评审）**：
- "缺少关键场景"误判率约60-70%
- "缺少结尾钩子"误判率约50%
- "伏笔操作未体现"误判率约40%
- 脚本显示36-40%通过率时，经人工复核实际通过率约70-80%

**常见误判模式**：
| 章纲用词 | 正文实际表述 | 误判原因 |
|---------|------------|---------|
| "念诵咒语" | "低声说出" | 关键词不匹配 |
| "图书馆" | "资料室" | 同义词替换 |
| "袭击" | "伏击/包围" | 近义词未覆盖 |
| "克制" | "但他没有"/"但他忍住了" | 间接表述 |
| "钩子"（隐晦） | 感官意象/诗意收束 | 非关键词模式 |

**处理原则**：先人工复核确认是否真正缺失，再决定是否补充。很多"需修改"章节实际已合格。

### 2. 章纲与正文不匹配

评审中经常发现章纲描述的内容与正文完全不同。原因可能是：
- 章纲文件被错误覆盖
- 章节编号错位
- 正文在之前某次修改中被替换

**处理原则**：如果正文内容自洽且前后章连贯，保留正文进行精简/补充。如果正文明显错位（如章纲写"西部荒野"但正文是"安其拉神殿"），按章纲重写。

### 3. 破折号超标

原文常有破折号密度>10个/千字的问题。精简时需要：
- 将部分破折号替换为逗号或句号
- 保留对话中断和戏剧性强调处的破折号
- 目标≤3个/千字

### 4. 子Agent写入失败

子Agent的 `write_file` 可能因文件过大或路径问题失败。验证方法：
```bash
wc -m /path/to/第{N}章.md
```
如果字数异常（0或原值未变），需要重新处理。
