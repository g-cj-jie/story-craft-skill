从旧角色Skill中吸收的可操作框架，按来源分类。供 novel-leader 在需要运营决策、编辑管理、发布执行时引用。

## 一、总编决策方法论（来源：chief-editor）

### 1.1 三维决策框架

所有重大决策从三个维度评估：

| 维度 | 核心问题 |
|------|---------|
| 市场可行性 | 目标读者是谁？多大规模？同类作品表现如何？（至少2部对标）平台政策是否支持？ |
| 创作可行性 | 团队有能力写好这个方向吗？能否支撑千万字篇幅？核心金手指表现空间够不够？ |
| 风险可控性 | 最大创作风险是什么？最大市场风险是什么？有没有Plan B？ |

**决策类型权重矩阵**：

| 决策类型 | 市场权重 | 创作权重 | 风险权重 | 必须参与 |
|---------|:------:|:------:|:------:|----------|
| 选题方向 | 50% | 30% | 20% | 全总监 |
| 世界观框架 | 20% | 60% | 20% | 剧情组 |
| 全书大纲 | 30% | 50% | 20% | 世界观组+人物组 |
| 重大剧情调整 | 30% | 40% | 30% | 主笔+人物总监 |
| 争议裁决 | 等权 | 等权 | 等权 | 相关组总监 |

### 1.2 裁决协议

**什么必须上报**：
- 改主线结局
- 写死核心角色
- 推翻已有世界观核心设定
- 两个总监级意见分歧无法调和
- 市场数据出现30%以上追读下跌

**什么各组可自决**：
- 单章章纲调整（不超出本卷大纲框架）
- 配角戏份微调
- 战斗方式选择（在设定规则内）
- 日常章节的节奏控制

**裁决五原则**：
1. 先听双方完整陈述，再问3个追问，然后裁决
2. 裁决必须附带"为什么选A不选B"的逻辑链，不能只说"我觉得A更好"
3. 当市场数据与创作直觉冲突时：数据优先，但保留创作直觉的"实验权"（小范围试）
4. 两个选择都有道理时：选"读者更可能追更"的那个，不是"更正确"的那个
5. 裁决后72小时内如果出现新证据，允许申请复议一次

### 1.3 边缘案例处理规则

- **大纲偏离**：写手写出偏离大纲但质量高的章节 → 召集剧情总监+主笔评估是否可以"以写手版本为新大纲"
- **读者大规模反对**：48小时内区分"情绪性反对"和"结构性反对"
- **写手过劳（存稿<5章）**：推迟爆更计划 + 联系主笔支援
- **两个平台相反建议**：以目标主平台意见为准

### 1.4 输出模板

**议题决策**：选题方向 → 目标读者 → 核心卖点(3个) → 对标作品(≥2部) → 风险评估 → 资源需求 → 决策 → 理由(逻辑链≥3步)

**争议裁决**：争议问题(A vs B) → 各方理由 → 裁决(选A/B/C) → 理由(逻辑链≥3步) → 风险提示 → 执行建议

## 二、运营策略（来源：ops-director）

### 2.1 发布节奏阶段表

| 阶段 | 章节范围 | 发布频率 | 目标 |
|------|---------|:------:|------|
| 新书期 | 第1-30章 | 每日2-3章 | 快速积累内容量，冲新书榜 |
| 免费期 | 第31-80章 | 每日2章 | 保持读者增长，建立阅读习惯 |
| 付费过渡期 | 第81-120章 | 每日2章 | 平稳过渡到付费，减少流失 |
| 稳定付费期 | 第121章+ | 每日1-2章 | 保持追读，追求订阅稳定 |
| 爆更节点 | 高潮章节 | 当日4-6章 | 最大化高潮冲击力+冲榜 |

**发布时间建议**：早8点(通勤) / 中午12点(午休) / 晚8点(睡前，流量最大)

### 2.2 付费节点决策矩阵

每项1-5分评分，总分≥20分→可开始付费；15-19分→暂缓1-2周；<15分→继续免费：

| 维度 | 1分 | 3分 | 5分 |
|------|-----|-----|-----|
| 收藏量 | <1万 | 3-5万 | >10万 |
| 追读率 | <20% | 30-50% | >60% |
| 剧情节点 | 平淡期 | 卷中段 | 高潮前夜 |
| 读者反馈 | 差评较多 | 中性 | 好评+催更 |
| 存稿量 | <10章 | 20-30章 | >40章 |

### 2.3 爆更策略

**触发条件**：
- 卷末大高潮：提前储备≥10章存稿 → 高潮当天4-6更
- 冲榜：平台推荐位+节日流量 → 配合爆更冲击榜单
- 粉丝活动：盟主/大额打赏 → 加更回馈（但控制频率）

**铁律**：
- 不能以写手过劳为代价
- 爆更后必须有3-5天存稿恢复期
- 不能降低单章质量——宁可少爆一章也不发水章
- 必须与剧情高潮同步——平淡期爆更=浪费流量

### 2.4 数据监控面板

| 数据指标 | 正常范围 | 预警阈值 | 行动 |
|---------|:------:|:------:|------|
| 追读率 | >40% | <30% | 分析剧情+节奏问题 |
| 收藏增长率 | >3%/天 | <1%/天 | 检查推荐位+推广效果 |
| 付费转化率 | >8% | <5% | 检查付费节点+前10章免费质量 |
| 章节完读率 | >70% | <50% | 该章可能有劝退内容 |
| 评论区活跃度 | >10条/章 | <3条/章 | 读者冷漠=最大危机 |

### 2.5 危机应对速查

| 危机类型 | 响应时限 | 行动 |
|---------|:------:|------|
| 追读率连续下降>15% | 48h | 联合品控+剧情组分析原因 |
| 章节引发大规模负面评论 | 24h | 联合社区管理+品控评估是否需修改 |
| 平台推荐位被取消 | 立即 | 了解原因+调整计划+寻找替代曝光 |
| 存稿低于5章 | 立即 | 通知主编→减缓发布→联系主笔支援 |
| 竞品突然爆发 | 48h | 分析对方做了什么→是否可借鉴（不是照搬） |

## 三、读者反馈处理（来源：community-manager）

### 3.1 反馈翻译表

读者说的不是创作建议——需要翻译成创作组能用的信号：

| 读者说 | 实际意思 | 翻译给创作组 |
|-------|---------|------------|
| "这章好水" | 本章没有信息增量 | "第X章信息增量不足，读者感知为水章" |
| "主角太弱了" | 最近战斗体验不好，没爽到 | "最近3章战斗缺少爽点，建议加一场展现主角优势的战斗" |
| "什么时候才能看到XX" | 对某个悬念失去耐心 | "伏笔F00X的回收节奏可能太慢，读者开始焦躁" |
| "这本书跟XX好像" | 缺乏差异化 | "最近内容可能过于套路化，建议检查独特性锚点" |
| "太好看了" | 真的好看——但需知道"哪里"好看 | "第X章的XX场景获得大量好评，这个方向值得复用" |

### 3.2 反馈四分类法

所有读者反馈按四类打标签：

1. **好评（继续保持）**：记录具体位置+好评内容
2. **差评（需要关注）**：记录具体位置+差评原因
3. **建议（参考不盲从）**：记录建议内容+可行性判断
4. **疑惑（需要加强）**：记录疑惑点+可能的信息缺口

**参考价值标注**：
- 高：≥3个读者独立提出类似观点 → 必须关注
- 中：1-2个读者提出+理由充分 → 需要关注
- 低：单个读者提出+理由牵强 → 可忽略

### 3.3 评论区管理原则

- 优先精选有具体分析的评论（即使差评）
- 不精选纯发泄/人身攻击/剧透/广告
- 回复代表"作者"，不说个人观点
- 不和读者吵架——举报比吵架有效
- 不在评论中补充正文没有的设定和剧情
- 对催更问题给模糊承诺不给具体承诺（"下周有惊喜" vs "下周三爆更"）
- 引导讨论"剧情走向/角色命运"——不引导讨论"写作水平"

### 3.4 核心粉丝画像

- 累计打赏≥100元 或 订阅+评论每章不落
- 在读者群活跃且有号召力
- 能提出有建设性的反馈

**维护方式**：提前1章剧透(需保密)、角色命名权/龙套冠名权、章末感谢名单、彩蛋预告

### 3.5 评论区危机应对

| 情况 | 应对 |
|------|------|
| 评论区负面占比>50% | 不删评→不反驳→收集→48h内输出分析报告→交品控+剧情组 |
| 读者群分裂/站队互撕 | 群公告→暂停讨论该话题→私聊关键人物→必要时清理极端言论 |
| 核心粉丝弃书/退款 | 私聊了解原因→记录→上报运营总监和总编 |
| 剧透/盗版传播 | 举报+移除+公告警告 |

**关键认知**：评论区活跃只占读者的5-10%，真正的数据在追读和完读率——不要忽略沉默大多数。

## 四、市场分析框架（来源：market-analyst）

### 4.1 三级报告体系

**每日速览（5分钟可读完）**：
自身数据快照 + 竞品异常动态 + 平台动态 + 今日关注（1个最关键信号）

**每周竞品周报**：
追踪同品类TOP10的收藏/订阅增速对比、更新频率对比、最新剧情节点、读者评论热词对比、可借鉴点

**每月市场分析**：
自身表现 + 竞品格局变化 + 上升/下降题材 + 平台政策变化 + 机会识别 + 风险预警

### 4.2 竞品分析五维度

| 维度 | 数据点 | 对我们意味着什么 |
|------|-------|---------------|
| 内容 | 主线进度/高潮频率/爽点类型 | 读者的口味偏好 |
| 更新 | 日更频率/爆更节奏/请假频率 | 我们的更新策略对标 |
| 数据 | 收藏/订阅/追读/榜单排名 | 市场的天花板在哪 |
| 读者 | 评论情感/讨论热点/催更强度 | 读者真正在乎什么 |
| 运营 | 推荐位/活动/粉丝运营 | 哪些运营动作有效 |

**竞品分析"三不"原则**：
1. 不只看数据好的竞品——数据差的竞品同样重要（知道"什么做法不行"）
2. 不只分析内容——更新策略、粉丝运营、推荐位节奏也是关键
3. 不建议"完全照搬"——竞品做得好不等于我们照搬就能好

### 4.3 趋势判断框架

区分"短期风口"和"长期变化"：

| 判断标准 | 短期风口 | 长期变化 |
|---------|---------|---------|
| 持续时间 | <3个月 | >6个月 |
| 驱动因素 | 单部作品带火 | 读者结构变化/平台战略调整 |
| 跟风作品 | 大量低价跟风 | 有质量的差异化跟进 |
| 读者留存 | 热度散去后读者流失 | 读者持续在品类内流转 |
| 应对策略 | 可以短期借势但不投入主力 | 需要认真考虑布局 |

### 4.4 数据到含义的翻译表

| 数据显示 | 可能的含义（按概率排序） |
|---------|---------------------|
| 收藏增速下降 | ①推荐位到期 ②开头几章劝退 ③品类热度下降 |
| 追读率提升但收藏不涨 | ①留住了核心读者但新读者增长慢 ②推荐位不够 |
| 追读率下降但评论增多 | ①某章引发了争议 ②剧情进入争议性方向 |
| 付费转化率低于均价 | ①免费章节质量不够 ②付费节点选择失误 ③读者付费意愿弱 |
| 某章完读率异常低 | ①该章开头写崩了 ②上一章的钩子太弱 ③该章被跳过了 |

## 五、发布执行流程（来源：release-manager）

### 5.1 发布前三步检查清单

**第一步：授权确认**
- [ ] 本章是否已通过终审？（无放行单=不能发）
- [ ] 本章是否已通过校对和连续性编辑？
- [ ] 发布时间是否符合发布排期？

**第二步：内容确认**
- [ ] 章节编号正确（第40章不能标成第39章）
- [ ] 章节标题正确
- [ ] 章末标记完整
- [ ] 回顾/预告符合平台要求

**第三步：格式确认**
- [ ] 已按目标平台规范适配
- [ ] 段落间距/段首空格/标题层级正确
- [ ] 特殊字符已过滤

### 5.2 各平台格式规范模板

对每个平台单独记录：
```
【平台名称】【段首规则】【段落间距】【标题格式】
【字数显示】【特殊限制】【分章规则】【定时发布】
```
核心规则：格式可以处理，内容一个字都不能改。

### 5.3 发布执行流程

1. 发布前30分钟：确认章节在队列中+格式已适配
2. 发布时间：准时发布（延迟不超过1分钟）
3. 发布后5分钟内：逐平台检查——标题？内容完整？格式不错乱？
4. 发布后30分钟：检查评论区——有没有读者反映看不到/乱码？
5. 记录发布日志

### 5.4 异常处理速查

| 异常 | 处理 | 时限 |
|------|------|:--:|
| 发布失败（技术原因） | 排查原因→手动补发 | 5分钟 |
| 内容被屏蔽/审核不通过 | 检查敏感词→必要时报主编→替换→重新提交 | 15分钟 |
| 章节顺序发布错误 | 紧急调整→如已有人读到→发公告更正 | 10分钟 |
| 格式错乱 | 重新适配格式→重新发布 | 5分钟 |
| 发布了错误版本 | 立即撤回→替换正确版本→如已有人读到→发公告 | 立即 |
| 平台宕机 | 等待恢复→恢复后立即补发 | 恢复后5分钟 |

### 5.5 待发布队列管理

队列条目格式：`【日期】→【时间】→【章节】→【平台】→【格式状态】→【终审状态】→【备注】`

规则：
- 每个条目必须有"终审放行单"才能排入
- 队列至少保持3天的提前量
- 存稿量<10章 → 立即通知运营总监

### 5.6 存稿预警级别

| 级别 | 存稿量 | 行动 |
|------|:------:|------|
| 黄色预警 | <10章 | 通知运营总监，开始关注 |
| 橙色预警 | <5章 | 减缓发布节奏，联系主笔支援 |
| 红色预警 | <3章 | 暂停爆更计划，紧急支援 |
