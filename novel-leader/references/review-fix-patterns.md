# 评审报告处理流程

## 触发条件

用户说"写小说"且 `评审报告/` 目录下有比上次写作更新的报告时。

## 处理流程

1. **读取报告**：按时间排序，读取最新报告
2. **分类问题**：按P0/P1/P2优先级分类
3. **并行修复**：使用 delegate_task 并行修复多个问题
4. **验证修复**：检查修改后的文件
5. **发送QQ汇报**：汇总修复内容

## 评审报告常见问题类型

### 大纲层问题
- 章纲归属不一致 → 以篇纲为权威
- 部纲章节分配表错误 → 对齐实际篇纲
- 伏笔编号冲突 → 重编号并更新总表

### 正文层问题
- 游戏/世界观细节矛盾 → 直接修改正文
- 技能名称不统一 → 全文搜索替换
- 现代物品去向不明 → 在早期章节补充交代

### 追踪表问题
- 人物未录入 → 从正文提取角色信息
- 伏笔编号冲突 → 统一编号体系
- 子剧情状态过期 → 从正文回填实际进度

## delegate_task 修复模板

```python
delegate_task(tasks=[
    {"goal": "修复ch1-2中D2游戏场景矛盾", "context": "具体问题描述+文件路径", "toolsets": ["file", "terminal"]},
    {"goal": "统一篇边界", "context": "权威边界+需要修改的文件", "toolsets": ["file", "terminal"]},
    {"goal": "重建追踪总表", "context": "需要更新的表+实际内容来源", "toolsets": ["file", "terminal"]},
])
```

## 选项B策略（大纲适配正文）

当正文已偏离大纲时，选择让大纲适配正文（而非重写正文）：
1. 创建参考文件（章纲摘要、写作参考、章纲参考）
2. 更新篇纲/卷纲反映实际轨迹
3. 更新四张总表回填实际内容
4. 保持已有正文不变

## 常见陷阱

1. **报告被外部agent覆盖**：Windows端Claude agent可能生成新报告。每次写前检查时间戳。
2. **修复引入新问题**：伏笔重编号时容易产生重复或截断。修复后验证无重复。
3. **参考文件路径**：参考文件可能在项目根目录而非写作状态目录下。用search_files确认。
