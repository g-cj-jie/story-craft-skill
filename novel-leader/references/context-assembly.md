# 上下文组装规则

## 核心原则：上下文隔离

**绝对禁止将前文章节全文带入当前写作上下文。** 前文章节全文是上下文污染源，会导致：
- 20章后：破折号"——"泛滥
- 40章后：整篇都是重复标点模式
- 句式、用词、节奏被早期章节污染

正确做法：每个子Agent（novel-write、novel-review、novel-context）获得干净上下文，只包含从 state 文件提取的结构化数据。

## 子Agent调用模板

### novel-write 子Agent调用

```
Agent(
  subagent_type: "general-purpose",
  description: "写第N章",
  prompt: """
  你是 novel-write。写第N章正文。

  ## 当前位置
  部X 卷Y 篇Z 第N章（全局第XXX章）

  ## 前文摘要
  [从 写作状态/近期摘要.md 读取，最近3章每章≤100字]

  ## 当前篇上下文
  [从 写作状态/当前篇简报.md 读取]

  ## 本章章纲
  [从 故事大纲/章纲/ch-N.md 读取]

  ## 相关人物状态
  [从 写作状态/人物状态.md 读取活跃人物]

  ## 关键精确数据（必须严格遵循，不可偏离）
  [从 写作状态/critical-data-snapshot.md 读取：技能面板、物品清单、技能点账目、实力面板、故事时间]
  以上数值为当前精确状态，写作时不得改变等级/数量/持有状态（除非本章章纲明确要求变化）。
  技能名称必须使用标准译名（如有术语表则严格参照）。

  ## 术语表
  [从 世界观设定/术语表.md 读取D2技能标准译名、WOW地名标准译名等]

  ## 活跃伏笔
  [从 写作状态/伏笔台账.md 读取活跃伏笔]

  ## 写作要求
  - 字数: 3000-5000字
  - 章节正文写入 章节正文/第N章.md
  - 变动清单作为独立文件写入 章节正文/第N章_变动清单.md
  - 正文为纯故事文本，不含任何元数据
  - 禁止使用序号标记分段
  - 详见 novel-write/references/ 下的规范文件
  """
)
```

### novel-review 子Agent调用

```
Agent(
  subagent_type: "general-purpose",
  description: "审查第N章",
  prompt: """
  你是 novel-review。审查第N章。

  读取 章节正文/第N章.md，按7维度评分。
  审查标准详见 novel-review/references/review-specs.md。

  特别检查：破折号"——"密度（每千字>5个 = 上下文污染，扣5分，标记为严重问题）。

  输出审查报告到 章节正文/第N章_审查报告.md。
  """
)
```

### novel-context 子Agent调用

```
Agent(
  subagent_type: "general-purpose",
  description: "更新第N章后状态",
  prompt: """
  你是 novel-context。第N章已通过审查，更新所有状态文件。

  读取 章节正文/第N章_变动清单.md 和 章节正文/第N章_审查报告.md。
  更新 写作状态/ 下所有文件（当前位置/人物状态/势力状态/伏笔台账/子剧情状态/近期摘要/当前篇简报）。
  检查是否需要归档。
  执行风格自检和大纲对齐。
  执行连续性交叉验证。

  规范详见 novel-context/references/state-specs.md。

  **必须输出**：
  1. 上下文更新确认表 — 逐文件列出具体变更，有✗必须说明原因
  2. 进展表 — 当前位置/字数/伏笔/子剧情/人物/势力/风格告警/连续写作章数
  3. 上下文压缩包 — 写入 写作状态/上下文压缩包.md（下一章子Agent入参的唯一上下文来源）
  """
)
```

### novel-context 输出验证（主会话执行）

novel-context 子Agent完成后，leader 必须检查其输出的两个表：

```
检查上下文更新确认表：
  - [ ] 11行全部为✓？（有✗则暂停，处理失败项）
  - [ ] 具体变更列非空？（空则要求重跑）
  - [ ] 超期伏笔告警？（有则提醒用户）
  - [ ] 风格自检结果？（破折号密度>5则标记警告，下章写前回顾）

检查变动清单：
  - [ ] 章节正文/第N章_变动清单.md 文件存在？
  - [ ] 变动清单包含必含字段（情节进展/子剧情/伏笔/人物/势力/新引入/未执行项）？
  - [ ] 若文件不存在或字段缺失 → 暂停，要求 novel-write 补写变动清单

检查进展表：
  - [ ] 上下文压缩包已重写？（必须确认。未重写则暂停）
  - [ ] 本篇累计进度？（≥90%则提醒准备下一篇纲）
  - [ ] 活跃子剧情有"即将完成"？（提醒用户准备该子剧情的填坑）
  - [ ] 关键数据快照已更新？（技能等级/物品/技能点/时间锚点数值一致）
```

两项检查通过后，leader 输出简要进度，然后继续下一章。**不提示用户开新会话**——上下文压缩包已确保下章子Agent获得干净上下文。

## 加载清单

### 必加载（每次写作都加载，从磁盘Read）
1. `写作状态/当前位置.md` — 当前部卷篇章位置
2. `写作状态/近期摘要.md` — 最近3章摘要（每章≤100字）
3. `写作状态/当前篇简报.md` — 当前篇上下文简报
4. `写作状态/critical-data-snapshot.md` — 关键精确数据快照（技能/物品/技能点/时间）
5. `故事大纲/章纲/ch-N.md` — 本章章纲

### 按需加载（仅加载与当前章相关的）
5. `写作状态/人物状态.md` — 只取当前活跃人物
6. `写作状态/势力状态.md` — 只取当前相关势力
7. `写作状态/伏笔台账.md` — 只取活跃状态的伏笔
8. `写作状态/子剧情状态.md` — 只取进行中的子剧情
9. `世界观设定/` — 仅在涉及具体设定时加载相关文件
10. `世界观设定/术语表.md` — D2/WOW专有名词标准译名（写作时必加载）

### 绝对禁止加载
- 前文章节全文（`章节正文/第N-1章.md` 等）
- 前文变动清单
- 前文审查报告
- 任何包含前文章节完整文本的内容

## 上下文压缩机制

**每章后 novel-context 生成 `写作状态/上下文压缩包.md`**。此文件是下一章子Agent入参的唯一上下文来源，替代历史对话。无论连续写多少章，子Agent始终获得干净上下文，效果等同于开新会话。

### 上下文压缩包内容

```markdown
# 上下文压缩包 — 第N章后

## 上一章核心要点（≤300字）
[第N章发生了什么：关键事件、重要对话、场景变化]

## 小说重点功能清单
- 世界观状态：[当前涉及的世界设定变更]
- 人物状态摘要：[主角+活跃配角当前状态，每人≤30字]
- 势力状态摘要：[活跃势力当前状态，每势力≤20字]

## 进度清单
- 本篇目标：[篇纲一句话]
- 本篇已完成章：N/18章
- 下章目标：[章纲一句话]
- 待推进子剧情：[ID+名称+当前进度%]

## 活跃钩子与伏笔
- 近期需填坑：[3章内需处理的伏笔ID+内容]
- 进行中伏笔：[活跃伏笔ID清单]
- 下章需埋/填：[章纲指定的伏笔操作]

## 关键精确数据（从 critical-data-snapshot.md 原样复制）
- 主角技能面板：[技能名+等级列表，不压缩]
- 随身物品清单：[物品+状态列表，不压缩]
- 技能点账目：[已获X/已用X/可用X，不压缩]
- 主角实力面板：[等级+经验+生命+法力，不压缩]
- 故事时间锚点：[当前日期/时间+累计天数，不压缩]

## 大纲对齐状态
- 当前章纲与正文偏离度：[无偏离 / 轻微(场景顺序调整) / 中度(部分场景替换) / 严重(整体脱离)]
- 累计偏离趋势：[稳定 / 扩大中 / 已校正]
- 纠偏指令（如有）：[下一章必须执行的回归章纲的操作]

## 最近3章摘要
[从近期摘要.md复制]

## 风格告警（如有）
[从当前篇简报和风格自检中提取的注意事项]
```

### leader 使用压缩包流程

每章开始前：
1. Read `写作状态/上下文压缩包.md` → 取得当前上下文
2. 将压缩包内容 + 章纲组装为子Agent入参
3. 子Agent获得干净上下文，不接触历史对话

**此机制确保第1章和第500章的上下文质量完全一致。** 如果用户某天主动开新会话，leader 读取压缩包即可无缝恢复，无需对话历史。
