# 大纲体系管理

## 双体系问题预防

### 问题描述
历史教训：项目中曾同时存在两套大纲体系（中文命名 vs 代码命名），导致部级章节分割点不一致、卷/篇纲完全错位、伏笔编号混乱。

### 预防措施
1. **只保留一套命名体系**：推荐中文命名（如 `第一部_穿越与新手期.md`），代码命名（如 `part-1.md`）应删除或归档
2. **统一权威来源**：以篇纲文件的章节范围为准，部纲/卷纲/章纲的"所属"字段必须与篇纲对齐
3. **定期一致性检查**：扫描所有章纲的"所属"字段，确保与篇纲边界一致

### 检查命令
```bash
# 检查是否有代码命名残留
find 故事大纲 -name 'part-*.md' -o -name 'vol-*.md' -o -name 'arc-*.md' | wc -l

# 检查章纲归属一致性（抽样）
grep '所属' 故事大纲/章纲/ch-{1,50,100,500,1000,2000}.md
```

## 幽灵伏笔处理

### 问题描述
篇纲文件中引用的 F 编号（如 F101-F109）不在伏笔总表中，成为不可追溯的"幽灵伏笔"。

### 处理流程
1. 扫描所有篇纲中的 F 编号引用
2. 与伏笔总表对比，找出不在总表中的编号
3. 将幽灵伏笔重编号为总表中未使用的编号（从 F038 起）
4. 更新篇纲文件中的引用
5. 将重编号后的伏笔添加到伏笔总表

### 检查命令
```bash
# 找出篇纲中的所有 F 编号
grep -roh 'F[0-9]\+' 故事大纲/篇纲/ | sort -u

# 找出伏笔总表中的所有 F 编号
grep -o 'F[0-9]\+' 故事大纲/伏笔总表.md | sort -u

# 对比差异
comm -23 <(grep -roh 'F[0-9]\+' 故事大纲/篇纲/ | sort -u) <(grep -o 'F[0-9]\+' 故事大纲/伏笔总表.md | sort -u)
```

## 篇纲密度检查

篇纲密度应均匀分布（每篇覆盖 15-25 章）。如果后期篇纲密度急剧下降（如每篇覆盖 50 章），需要增补篇纲。

```bash
# 检查每部的篇数
ls 故事大纲/篇纲/ | grep '第.*篇' | wc -l
```

## 章纲归属字段统一

章纲文件中的"所属"字段格式应统一为 `第X部/第Y卷/第Z篇`。
常见问题：
- 卷编号回退（如 ch-201 标注第五卷，ch-301 标注第三卷）
- 篇名格式不统一（`第十五篇` vs `暴风城篇` vs `第30篇`）

修复：以篇纲文件为权威，批量修正所有章纲的"所属"字段。
