# novel-write

## 适用边界

由 novel-leader 以**子Agent方式**调用。每次调用获得独立干净上下文，只看到传入的state数据和章纲，看不到前文章节全文。两种模式：
- **首次模式**：接收章纲+state上下文包，写新章节
- **修改模式**：接收审查问题清单，修改当章

不适用：非小说的文字创作、无章纲的自由写作。

**输出方式**：正文写入 `章节正文/第N章.md`，变动清单写入 `章节正文/第N章_变动清单.md`。不在主会话中输出完整正文。

## 执行主流程

### 步骤1（首次模式）：读取输入并写作

接收上下文包（当前位置+前3章摘要+篇级上下文+相关人物/势力/伏笔/子剧情状态）和章纲。按写作规范输出正文（3000-5000字）+ 完整变动清单。

### 步骤1.5：章纲对照自检（写作后必须执行）

写完全文后，逐项对照章纲检查（变动清单前执行）：
- [ ] 本章目标是否达成？（核心事件是否发生）
- [ ] 章纲指定的场景是否全部覆盖？（1-3个场景）
- [ ] 章纲指定的伏笔操作是否全部执行？
- [ ] 本章内容是否超前于章纲规划的节奏范围？（地点/角色/事件级别）
- [ ] 字数是否在3000-6000字范围内？（<3000或>6000硬阻断，直接不合格）
- [ ] 结尾是否有明确的情节钩子？（不能以诗意收束或总结性语句结尾）

有任一项未达成，必须在变动清单"未执行项"中明确说明原因。
若核心目标未达成（偏离>50%），本章视为不合格，不得提交审查，必须重写。

### 步骤1.6：关键场景嵌入（避免评审误报）

**重要**：评审脚本通过关键词匹配检测关键场景，为避免误报，写作时需确保：

1. **关键场景使用章纲原文关键词**
   - 章纲写"苏晨挥剑攻击"，正文中至少出现一次"挥剑"或"攻击"
   - 可以用同义词丰富描写，但关键词本身必须出现至少一次

2. **结尾钩子必须明确**
   - ✅ 好的钩子："门外传来脚步声。"
   - ✅ 好的钩子："苏晨握紧了拳头，眼中闪过一丝决绝。"
   - ❌ 坏的钩子："苏晨知道，这条路还很长。"（总结性语句，非钩子）
   - ❌ 坏的钩子："夜色渐深，一切归于平静。"（诗意收束，非钩子）

3. **伏笔操作要在正文中体现**
   - 章纲写"埋设伏笔：苏晨注意到异常"，正文中必须有苏晨注意到异常的具体描写
   - 不能只在变动清单中记录，正文必须包含

### 步骤2（修改模式）：按问题清单修改

接收上一版正文 + novel-review 的问题清单。逐条回应修改，输出修改后正文 + 修改回应（逐条说明修改方式或未修改理由）+ 更新后的变动清单。

### 步骤3：写作规范约束

写作中遵循：语言风格一致、场景不超过3个、节奏按类型控制、伏笔自然融入、人物不OOC、禁止水字数、章节内禁止使用序号标记分段如 `## 一` `1.` 等，场景切换用空行/分隔符/叙事过渡（详见 references/）。

## 字数硬约束

| 字数范围 | 评审结果 | 说明 |
|----------|----------|------|
| 3000-6000字 | ✅ 满分 | 目标范围 |
| <3000字 | ❌ 硬阻断 | 直接不合格，需扩充，不送LLM |
| >6000字 | ❌ 硬阻断 | 直接不合格，需拆分或精简，不送LLM |

**写作时务必控制在3000-6000字范围内。**

## 子Agent质量控制

### ⚠️ 模型选择（关键）

**禁止使用 glm-4-flash。** 该模型的 tool calling 不可靠——声称写入文件但实际不调用 write_file。必须使用 mimo-v2.5 或更强模型。

推荐调用方式：`hermes chat -q "..." --model mimo-v2.5 --provider custom -Q`（不使用 delegate_task，因 model override 不生效）。

详见 novel-leader/references/model-config.md。

### 弱模型常见问题（如glm-4-flash、免费tier模型）
- 段落间重复同一表达（同一句话改头换面出现3-5次）
- 抽象情感堆砌代替具体感官描写（"坚定的光芒""深吸一口气"反复出现）
- 章纲理解表面化，写出的内容与章纲要求有偏差
- 在正文中混入章纲原文或写作要求等非故事文本
- 结尾总是"他知道前方的路还很长，但他已经做好了准备"

### 应对策略
1. prompt中明确加入："禁止同一表达在不同段落重复。禁止使用'坚定的光芒''深吸一口气'等陈词滥调。"
2. 强调感官细节："用触觉、嗅觉、听觉的具体描写代替抽象情感描述"
3. 写后必须经过 novel-review 评审环节能捕获大部分质量问题
4. 如果质量持续不达标，考虑提升 delegation.model 配置

## 输出要求

输出分为两个独立部分，严禁混淆：

### 一、正文（纯故事文本）
章节标题 + 正文内容（3000-5000字）。正文为纯故事文本，不含任何元数据、变更记录、标记或变动清单。字数自检结果也不纳入正文。

### 二、变动清单（独立元数据）
在正文之后单独输出，包含：情节进展、子剧情推进、伏笔操作、人物变化、势力变化、新引入元素、未执行项。变动清单不属于正文内容。

### 三、修改模式增加
修改回应（逐条回应问题清单），同样作为独立元数据，在正文之后单独输出。

### 四、字数自检
以独立标注形式输出实际中文字数，不纳入正文。
