# novel-write 输出格式

## 核心原则

本章输出写入两个**独立文件**，严禁混淆：

- **正文** → 写入 `章节正文/第N章.md`：纯故事文本。不含任何元数据、变更记录、标记、变动清单或其他非故事内容。
- **变动清单** → 写入 `章节正文/第N章_变动清单.md`：元数据。独立文件，不纳入正文文件。

**禁止在主会话中输出完整正文。** 正文和变动清单必须写入文件，子Agent只向leader返回简要摘要（字数、关键事件一句话）。

---

## 正文文件 `章节正文/第N章.md`（纯故事文本）

正文仅包含章节标题和故事内容，不附加任何其他信息。用Write工具写入文件：

```
# 第N章 [章节标题]

[正文内容，约3000-5000字，纯故事文本]
```

---

## 变动清单文件 `章节正文/第N章_变动清单.md`（独立元数据）

变动清单写入独立文件。不属于正文内容，不在正文文件中出现：

```markdown
## 本章变动清单

### 情节进展
- 篇主线推进: [具体推进了什么]
- 卷主线推进: [如有]

### 子剧情推进
| 子剧情ID | 本章进展 | 进度变化 |
| BP-XX | 简述 | 30%→45% |

### 伏笔操作
| 操作 | 伏笔ID | 内容 |
| 新埋 | FS-XX | 简述 |
| 填坑 | FS-YY | 如何揭晓 |
| 推进 | FS-ZZ | 推进方式 |

### 人物变化
| 人物ID | 变化内容 |

### 势力变化
| 势力ID | 变化内容 |

### 新引入元素
- 新人物/新地点/新物品: [如有，简要描述]

### 未执行项（如有）
- 章纲要求XX但本章未执行，原因：[...]
```

## 修改模式额外输出

修改回应同样是独立的元数据块。在正文之后、变动清单之前单独输出：

```markdown
## 修改回应

### 问题清单逐条回应
1. [问题1]: 已修改 → [修改方式]
...
N. [问题N]: 未修改 → [理由说明]
```

## 两种模式

### 模式A：首次写作
输入：上下文包 + 章纲
输出：正文（纯故事文本） + 变动清单（独立元数据）

### 模式B：审查后修改
输入：上一版正文 + novel-review 的问题清单 + 修改建议
输出：修改后正文（纯故事文本） + 修改回应（独立元数据） + 变动清单（独立元数据）
