# 状态文件规范

novel-context 维护 `写作状态/` 下8个状态文件。每章通过审查后增量更新，不追加历史。

**每次更新后必须输出两个结构化表格**：上下文更新确认表 + 进展表。格式详见本文末尾。这是验证状态更新实际落地的唯一凭证。

---

## 1. current-position.md — 当前位置

```markdown
- 部: X / 5
- 卷: Y / 8
- 篇: Z / 7
- 章: N（本篇内第N章，全局第XXX章）
- 下一章: N+1
- 下一章章纲: 已就绪 / 待生成
- 状态: WRITING / REVIEW_*
- 最后更新: YYYY-MM-DD HH:MM
```

更新：章号每章+1；到篇边界篇号+1章号=1；到卷边界卷号+1篇号=1。

## 2. character-state.md — 人物当前状态

只记录活跃人物当前态，不含历史：

```markdown
### CH-001 主角名
- 身份/境界/位置/当前目标
- 关键关系变化跟踪
- 最近变化: 第N章 → [简述]
- 最后活跃章: 第N章
```

更新规则：本章有变化的人物更新对应字段；连续30章未出现→标记休眠移到归档；死亡/退场→移除到归档。

## 3. faction-state.md — 势力当前状态

同人物状态格式。记录当前活跃势力：实力/控制区域/盟友敌人/当前目标/最近事件。

## 4. foreshadow-ledger.md — 伏笔台账

只含活跃伏笔（已填和作废移到归档）：

| ID | 内容 | 埋设 | 计划填 | 预计篇 | 剩余期限 | 状态 |
|---|---|---|---|---|---|---|
| FS-005 | XX谜团 | 部1卷2篇3章12 | 部2卷5 | 篇15 | 还剩3篇 | 待填 |

新埋伏笔追加行；填坑改状态为已填；超期（剩余期限≤0）标红回报leader。

## 5. subplot-state.md — 子剧情状态

| ID | 名称 | 起始篇 | 预计结束篇 | 进度% | 本篇进展 | 状态 |

进度%为主观评估。状态：进行中/即将完成(>80%)/已完成/暂停。

## 6. recent-summary.md — 最近3章摘要

滚动记录，每章≤100字。永远是最近3章，旧摘要删除不保留。

## 7. arc-brief-current.md — 当前篇简报

篇开始生成，篇结束废弃：
- 篇名/目标/已发生关键事件（每条≤20字）
- 当前篇内位置
- 即将发生的关键事件预告

### 故事时间锚点

- 当前故事日期/时间：第X天 HH:MM
- 距穿越累计时间：X天
- 最后更新：第X章

### 更新规则

- **每章强制更新**：物品持有状态、技能等级、技能点账目
- **首次出现时登记**：新技能、新物品
- **状态变化时更新**：物品消耗、技能升级、技能点使用
- **数值计算必须验证**：已获技能点 = 等级，已用 + 可用 = 已获

此文件内容在上下文压缩时**不压缩数值和列表**，原样传递。写入 `写作状态/critical-data-snapshot.md`。

## 归档规则

- 时机：人物退场/伏笔填坑(篇结束时)/子剧情完成(篇结束时)/势力覆灭
- 位置：`写作状态/归档/` 下按类型分文件
- 模式：append-only，按时间排序
- 状态文件只保留活跃项，归档后从状态文件中移除

## 自检清单

每次更新后检查：
- [ ] current-position 章号正确递增
- [ ] character-state 本章变动人物无遗漏
- [ ] foreshadow-ledger 本章伏笔操作全部记录
- [ ] recent-summary 已滚动（旧摘要已删除）
- [ ] 需归档项已归档
- [ ] 所有文件"最后更新"时间正确

## 上下文净化与保留原则

每章压缩的核心问题：**下一章写手是否需要这条信息才能写出准确的内容？** 需要则保留，不需要则丢弃。

### 永久保留（进入 state/，跨章节可用）

- 小说大纲（全书+分卷+当前篇纲）
- 资料设定（世界观、角色档案、技能体系）
- 未完成伏笔与钩子（foreshadow-ledger.md）
- 最近三章摘要（recent-summary.md）
- 人物/势力当前完整状态（character-state.md / faction-state.md）
- 子剧情进度追踪（subplot-state.md）

### 临时保留（当前章使用后丢弃）

- 正在写的章节全文
- 参考的前一章全文（用于连续性对照）

### 立即丢弃（不进入任何记忆文件）

- 超过三章的历史章节全文
- 已废弃的段落版本
- 已回收伏笔的详细回收过程（只保留"已回收于第X章"一行标记）
- 过渡性场景的细节描写
- 非核心配角的日常对话
- 中间状态的草稿和修改记录

### 伏笔分类原则

- **核心伏笔（未回收）**：涉及主线的关键伏笔——起源谜团、核心秘密、最终目标相关
- **进行中钩子**：正在发展的支线线索——势力动态、人物暗线、阶段性目标
- **已回收伏笔**：本章确认回收的伏笔→标记状态为已填，保留一行记录后移入归档
- **人物线索**：关键角色当前未完成的状态和走向

新增伏笔时先判断：这是新伏笔还是已有伏笔的延伸。如果是延伸→更新已有条目而非新建。

### 状态文件大小控制

- character-state.md 每人条目不超过8个字段
- faction-state.md 每势力条目不超过6个字段
- recent-summary.md 永远只保留最近3章，每章100字以内
- 所有状态文件单文件不超过2000字——它们是快照，不是报告

## 风格自检与大纲对齐

每次更新状态文件后，对本章正文执行风格自检和大纲对齐。如发现问题，在输出中追加风格警告。

### 风格自检

1. **破折号密度**：统计全章"——"出现频次。密度>5个/千字→标记为"上下文污染警告：破折号密度过高，建议开新会话"。密度3~5/千字→标记为"风格偏移风险：破折号使用偏多"
2. **时间跳跃异常**：如果本章时间跨度超过一周，标记提醒下一章写手注意时间锚定
3. **关键数据一致性**：人物等级、技能等级、关键物品数量——必须与前章状态文件记录一致
4. **叙事语气漂移**：与前三章相比，叙事节奏（偏快/偏慢）、对话占比、描写密度是否有显著变化。如有显著偏离→标记

### 大纲对齐与阻断规则

与章纲交叉验证：
1. 本章核心事件是否在章纲框架内？
   - 完全在框架内 → 正常
   - 部分偏离（场景顺序调整、细节扩展、配角自主行为） → 标记警告，继续
   - 严重偏离（核心场景/地点/事件级别完全不同于章纲，偏离度>50%） → **阻断：不更新状态文件，回报leader并附"大纲偏离阻断报告"**
2. 本章新出现的人物/地点/物品是否已在资料设定中登记？未登记需标记
3. 本章是否使用了前文未交代的设定？如有需标记为"待补充设定说明"
4. 本章是否引入了新的规则级设定（改变战斗逻辑、能力体系、穿越规则等）？如有 → 标记"待文档化：XX设定（第X章引入）"，需写入对应世界观文件

#### 大纲偏离阻断报告格式

触发阻断时，不执行正常的状态更新流程，改为输出：

```
【大纲偏离阻断】第X章
偏离描述：[核心事件/场景/地点/人物/事件级别 具体偏离了什么]
偏离程度：[%]
章纲预期：[章纲规划的内容]
正文实际：[实际写作的内容]
建议决策：A) 正文回退重写，严格按章纲  B) 以正文为准，重构大纲
影响评估：若采纳B方案，预计需修改 [X] 个大纲文件
```

阻断时状态文件不更新，当前章标记为"待决策"。leader 收到阻断报告后必须向用户提问。

### 风格警告格式

在输出报告的末尾追加：
```
## 风格警告
- [警告内容]（第X章发现）
```

标记了的警告在写下一章时由 novel-leader 传达给 novel-write 以回顾修正。

## 上下文更新确认表（强制输出）

novel-context 每次执行完毕后，必须输出此表。它是验证8个状态文件+归档+自检+交叉验证是否全部执行的**唯一凭证**。禁止笼统写"已更新"，必须列出具体变更内容。

```markdown
## 上下文更新确认表 — 第N章

| 状态文件 | 状态 | 具体变更 |
|---------|:----:|------|
| 写作状态/当前位置.md | ✓ | 部2卷3篇5章4→章5（全局第284→285章） |
| 写作状态/人物状态.md | ✓ | CH-001: 境界更新为元婴初期，位置移至青云城；CH-003: 关系标记"盟友→信任"；其他无变化 |
| 写作状态/势力状态.md | ✓ | FC-002: 控制区域新增洛阳分舵；其他无变化 |
| 写作状态/伏笔台账.md | ✓ | 新埋FS-042(天外陨铁来源线索)；填坑FS-018(李潇玉佩秘密→揭示为钥匙)；推进FS-015；超期告警: FS-003(超过预定3篇) |
| 写作状态/子剧情状态.md | ✓ | BP-01: 40%→45%(发现新线索)；BP-03: 70%→85%(即将完成) |
| 写作状态/近期摘要.md | ✓ | 淘汰第281章摘要，新增第285章摘要(98字) |
| 写作状态/当前篇简报.md | ✓ | 关键事件+1(共7条)；篇内位置12→13/18 |
| 写作状态/关键数据快照.md | ✓ | 技能等级无变化；物品[XX]状态更新；技能点账目[已用X/可用X]；故事时间推进X天 |
| 归档检查 | ✓ | FS-018移至归档(已填坑)；无其他待归档项 |
| 风格自检 | ✓ | 破折号密度1.2个/千字(正常)；无时间跳跃异常；语气无漂移 |
| 连续性交叉验证 | ✓ | 通过。人物/势力/伏笔状态与正文变动清单一致 |
```

**✗标记规则**：若某项未执行或执行失败，标记为✗并在"具体变更"列写明原因和补救动作。leader 看到✗必须暂停写作循环。

## 进展表（强制输出）

紧随确认表之后输出。是当前写作进度的快照，供 leader 和用户一眼掌握全局状态。

```markdown
## 进展表 — 第N章后

| 维度 | 数据 |
|------|------|
| 当前位置 | 部2/5 卷3/8 篇5/7 章5/18（全局第285章） |
| 本章字数 | 4,120字 |
| 本篇累计 | 21,080字 / 目标60,000~80,000字（30.1%） |
| 主角等级 | Lv X（经验XX%） | 技能点已用X/可用X |
| 活跃伏笔 | 23个待填 / 1个超期（FS-003） |
| 活跃子剧情 | 5个进行中 / 1个即将完成（BP-03:85%） / 0个已完成 |
| 活跃人物 | 12人活跃 / 2人休眠（CH-015,CH-022） / 0人近期退场 |
| 活跃势力 | 6个 |
| 风格告警 | 无 |
| 连续写作章数 | 当前会话已写5章 |
| 上下文压缩包 | 已重写（`写作状态/上下文压缩包.md`） |
```

**上下文压缩包**是下一章子Agent入参的唯一上下文来源。leader 每章开始前读取此文件组装子Agent入参，效果等同于开新会话。格式详见 novel-leader/references/context-assembly.md。

**连续写作章数**从1开始计数，每章+1。仅做信息展示——上下文压缩包已确保干净上下文，无需开新会话。
